# Roswaal style guide

How the TypeScript in this repository is written. It exists so that code
written months apart, by different hands, reads as one codebase — and so that
a review can point at a rule rather than at a preference.

**The base is the [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html).**
Where this file says nothing, that guide applies. Where this file differs, this
file wins, and every difference says why. Luau that Roswaal writes or ships is
formatted by StyLua with `stylua.toml`; this guide is about the tool's own code.

Rules marked **(tool)** are enforced by Biome or `tsc` and need no reviewer.
The rest are for review.

---

## 1. Formatting

| Rule | Why |
|---|---|
| **Tabs** for indentation. **(tool)** | Every file already uses them, and so does the Luau side (`stylua.toml`). Google's tooling uses two spaces; its guide sets no rule. |
| **Double quotes**, single quotes only to avoid escaping. **(tool)** | Much of the code is prose and emitted Luau, both full of apostrophes. Google says single; this is a deliberate deviation. |
| **Semicolons**, always. **(tool)** | Google requires them. |
| **Trailing commas** in every multi-line list. **(tool)** | One-line diffs when a list grows. |
| **100 columns** for code, **80** for comments and prose. **(tool for code)** | Comments already wrap at 80. Generated files and long prose data (`releases.ts`, docs pages) are exempt from the code limit. |
| Imports sorted: packages, then `node:` modules, then relative. **(tool)** | Biome sorts them; nobody should spend a review on it. |

Formatting is applied by `npx biome format --write` (see §9). A reformat is its
own commit, listed in `.git-blame-ignore-revs`, never mixed into a change.

## 2. Files and modules

- **File names.** `lowerCamel.ts` for modules, `PascalCase.tsx` for a file whose
  main export is a React component, `kebab-case.mjs` for build scripts, and
  `flatlowercase.test.ts` for tests. *Google says `snake_case`; renaming 350
  files would break history and every docs link for no gain.*
- **Named exports only.** No `export default`. **(tool)** The exceptions are files a tool
  reads by its default export: `vite.config.ts`, `vite.web.config.ts` and the virtual-module
  declaration in `src/web/virtual.d.ts`.
- **No `export *`.** Re-export names explicitly, so a reader can see what a
  module offers without opening the one behind it. **(tool)**
- **`import type`** for an import used only as a type. **(tool)**
- **Relative imports carry `.js`** (`./store.js`, `./App.jsx`), as ESM requires.
- **A file has one job.** Past ~800 lines, look for the second job and split it
  out. Past 1,500 it needs a reason written in its header.
- **`src/core` imports nothing platform-specific**: no `node:*`, no DOM.
  **(tool)** It is shared by the daemon, the web worker and the CLI.
- **Generated files** say so in their first line — `// Generated by scripts/x. Do
  not edit by hand.` — and are listed as `linguist-generated` in
  `.gitattributes`.

## 3. Naming

| Kind | Style | Example |
|---|---|---|
| Types, interfaces, classes, components | `PascalCase`, no `I` prefix | `OpenProject`, `SaveQueue` |
| Functions, variables, parameters | `lowerCamelCase` | `writeGraph` |
| Module-level constants that never change | `CONSTANT_CASE` | `SCHEMA_VERSION` |
| A *function* that builds a value | `lowerCamelCase`, even at module level | `membersPage()`, not `MEMBERS_PAGE` |
| Private members | TypeScript `private`, no `#`, no `_` | `private pending` |
| Hooks | `useX` | `useEditor` |

- **Acronyms are words**: `escapeHtml`, `readRbx`, `nodeId`.
- **Booleans read as a state or a question**: `dirty`, `open`, `isPrefixExpression`.
- **Name the result, not the mechanism.** `entryPath` says what you get;
  `safeJoinButNotRoot` says how.
- **Spell it British** in user-facing text (`colour`, `initialise`) — the docs
  and UI already do. Identifiers follow the same spelling where they name a
  user-facing idea.

## 4. Types

- **`interface` for object shapes, `type` for unions and aliases.** **(tool)**
- **String unions, never `enum`.** **(tool)** *Google allows `enum`. Unions
  serialise to JSON as they are, and every saved graph is JSON.*
- **No `any`.** Use `unknown` and narrow it. **(tool)**
- **Casts (`as`) and non-null assertions (`!`) need a reason.** Prefer a type
  guard or a typed accessor. Each one left in place has a comment saying why
  the compiler cannot know what we know. **(tool: warning)**
- **No `as {…}` on node config.** `NodeConfig` is loose on purpose; read it
  through a typed accessor (`castModeOf(config)`, `functionNameOf(node)`) so the
  shape is written down once.
- **`@ts-expect-error` only with a description**, and only where a dependency is
  untyped. Never `@ts-ignore`. **(tool)**
- **Annotate the return type of every exported function.** Inference is fine
  inside a module.
- **Absence is `undefined`.** Use `null` only where JSON or the DOM gives you one.
  Compare with `== null` when either may arrive. Do not mix the two in one API.

## 5. Functions

- **Top-level functions are `function` declarations**, not arrow constants.
  **(tool)** Arrows are for callbacks.
- **More than three parameters, or any boolean flag, becomes an options object.**
  `compile(script, registry, { comments: true })`, never `compile(script,
  registry, true)`.
- **A function does one thing at one level.** Past ~60 lines, look for the
  steps inside it and name them. Past ~150, it needs a reason.
- **No side effects at import time.** A module that builds a server, opens a
  socket or reads the disk when imported does it in a function its caller
  calls (`createDaemon()`), so tests and the CLI can import it freely.

## 6. Errors

One model per layer, so a caller knows what to expect without reading the body:

| Layer | Model |
|---|---|
| The compiler and validators | **Collect diagnostics** on a node and pin. Never throw for a problem in a graph. |
| The Luau lexer and parser | **Collect diagnostics**; recover and carry on. |
| File and place I/O (`src/server`, `src/core/rbx`, `unzip`) | **Throw a typed `Error` subclass** (`RbxError`, `ZipError`, `HttpError`). Export the class so callers can test for it. |
| The API (`routes.ts`) | **Answer `{ error, code? }`**. A known problem is 4xx; anything unexpected is **500**, never 400. |
| The editor | **Show it** through `notify` or the problems list. Never swallow it. |

- **Only `Error`s are thrown.** **(tool)**
- **Every empty `catch` and every `.catch(() => {})` says why** ignoring the
  error is safe, in a comment on the same line or above. **(tool, comment
  satisfies it)**
- **`errorMessage(err)`**, not `(err as Error).message`.

## 7. Comments

Comments here are long on purpose, and that is a house rule worth keeping: a
code reader has already decided to spend the time, and the expensive thing is a
decision nobody wrote down. Google asks the same — say *what* and *why*.

- **`/** … */` documents a declaration** and sits **directly above** it, with
  nothing in between. Inserting code between a doc comment and its function is
  how ~60 comments ended up describing the wrong thing; move the comment with
  the code.
- **`//` inside a function body**, never `/** */`.
- **Every file opens with a header** saying what it is for and what it is not.
- **Say why, and what would break.** "Resolved inside the loop so it is read
  again on every pass" — not "resolve condition".
- **No history.** "Used to", version numbers and "until 0.30.0" belong in the
  commit message and `NOTES.md`. A comment describes the code as it is.
- **No commented-out code**, and no `TODO` without an issue or a named version.

User-facing text is the opposite: short. A label names the result, a node
description is one sentence, and the detail goes on a docs page. See
`docs/WORDING.md`.

## 8. React

- **One component per file** for anything over ~80 lines; small helpers may sit
  beside it.
- **Props are an `interface XProps`**, destructured in the signature.
- **State lives in one place.** Graph documents in the store; preferences in
  `usePreferenceSync`; nothing read from `localStorage` directly in a component.
- **Effects clean up** every listener, timer and observer they add. An effect
  that cannot clean up (a save) does not belong in an effect — see `saveQueue.ts`.
- **`react-hooks/exhaustive-deps` is on.** **(tool)** A disable needs a comment
  saying which dependency is left out and why it cannot go stale.
- **Class names go through `cx()`**, and a modifier class is prefixed with its
  block: `node node--reroute`, never `node reroute`. An unprefixed modifier
  inherits every `.reroute` rule in the stylesheet.

## 9. Tooling

```sh
npx biome check .          # format, import order and lint, as CI runs it
npx biome check --write .  # fix what can be fixed
npm run typecheck          # tsc, strict
npm test                   # vitest
```

- **Biome** formats, sorts imports and lints (`biome.json`). Its defaults
  already match §1.
- **`tsc`** runs `strict`, with `noUnusedLocals`, `noUnusedParameters`,
  `noImplicitReturns`, `noImplicitOverride` and `noFallthroughCasesInSwitch`.
  `scripts/` is type-checked too.
- New lint rules start as **warnings** and become errors once the code base is
  clean of them, so a rule never lands with a thousand-line fix attached.

## 10. Review checklist

Before a change is done:

1. Tests cover the behaviour, and the suite is green on the working tree *and*
   the committed tree.
2. Every rule above that a tool does not check: names, casts, error model,
   comment placement, option objects, function length.
3. A graph, node or scope change is checked on all four surfaces: the editor
   canvas, Node Design's canvas, the docs pages, and the docs' drawn graphs.
4. The release note says what changed, not why; the why is in `NOTES.md`.
